# Why does my agent...?

An index of what goes wrong when an AI agent edits a real Figma file, written the way a designer would describe it. Find the symptom, read the one-line cause, then follow the link to the note that holds the fix. The notes are the source: this page only points at them, so the fix is never restated here.

Most of these were paid for in production through [figma-console-mcp](https://github.com/southleft/figma-console-mcp) and its `figma_execute` tool. Many apply to any agent that runs Plugin API code, including `use_figma` on the official Figma MCP server. A few belong to one server only, and the linked note says which. See [works-with.md](works-with.md) for what each skill needs.

**Tip.** You can paste a symptom and its link into your agent: "Read this note and tell me whether this is what happened to my file."

## Silent no-ops: "it said done, and nothing changed"

- **"My agent says it changed the color, but nothing changed."** In one sweep through the figma-console bridge, a few writes under a locked parent did not take and raised no error, though each layer read `locked: false`. Figma's typings say `locked` does not block plugin writes, so the cause is not established. A read-back of the changed property catches it either way. [Writes under a locked ancestor did not take through the figma-console bridge](../skills/figma-canon/references/field-notes.md#writes-under-a-locked-ancestor-did-not-take-through-the-figma-console-bridge)
- **"Its own check came back green, and the change is still missing."** The read-back compared a stand-in (color, opacity) that stays the same precisely when nothing was written, instead of the property that was supposed to change. [Post-approval: write execution rules](../skills/figma-preflight/SKILL.md#post-approval-write-execution-rules)
- **"It set a layer to Fill container, and the layer stayed Fixed."** The sizing was set before the layer was added to its parent. [Layout sizing: order matters](../skills/figma-canon/references/plugin-api-core.md#layout-sizing-order-matters) · [Set sizing AFTER append](../skills/figma-canon/references/auto-layout-canon.md#set-sizing-after-append)
- **"It set Fill container, resized the layer, and it went back to Fixed."** `resize()` resets the sizing modes to Fixed. [Resize order trap](../skills/figma-canon/references/auto-layout-canon.md#resize-order-trap)
- **"It moved a layer inside an auto layout frame, and the layer ended up somewhere else."** Coordinates set on a child of an auto layout frame are accepted and then ignored: the layout restacks the child. [Absolute coordinates in an auto layout parent: accepted and ignored](../skills/figma-canon/references/auto-layout-canon.md#absolute-coordinates-in-an-auto-layout-parent-accepted-and-ignored)
- **"It switched pages, and kept working on the old one."** Assigning `figma.currentPage` directly is silently broken; only the async page setter works. [Page switching: async only](../skills/figma-canon/references/plugin-api-core.md#page-switching-async-only)
- **"It recolored a line icon, reported success, and the icon looks the same."** A monoline icon usually paints on strokes, and the loop only touched fills. [Deriving the dark version of a screen](../skills/figma-canon/references/plugin-api-anomalies.md#deriving-the-dark-version-of-a-screen-setexplicitvariablemodeforcollection-and-the-raw-hex-detector)
- **"It widened a card from our component, and the background layer kept its old width."** The width of a layer inside an instance belongs to the main component: `resize` on it does not throw and does not apply. [Instance sublayers: width and constraints also belong to the master](../skills/figma-canon/references/plugin-api-anomalies.md#instance-sublayers-width-and-constraints-also-belong-to-the-master)
- **"The image fill tool said it worked, and the layer has no image."** `figma_set_image_fill` returns a valid hash, reports "applied to 0 node(s)" and writes nothing. [figma_set_image_fill: MCP tool bug](../skills/figma-canon/references/plugin-api-anomalies.md#figma_set_image_fill-mcp-tool-bug)
- **"Its screenshots before and after the edit are identical."** The edit changed nothing, or it is invisible by design, or the plugin export cache returned the same bytes after a real change. [REST /v1/images renders stale cloud state after plugin edits](../skills/figma-canon/references/plugin-api-anomalies.md#rest-v1images-renders-stale-cloud-state-after-plugin-edits)
- **"Its debug output is empty."** `console.log` does not reach the agent: the script has to `return` its data. [console.log: not the output channel](../skills/figma-canon/references/plugin-api-data.md#consolelog-not-the-output-channel)
- **"It added a timeout guard to a slow script, and the guard never fired."** Through the figma-console bridge, `setTimeout` did not fire in a `figma_execute` script. Figma's typings declare `setTimeout`, and the cause is not established. [`setTimeout` did not fire through the figma-console bridge](../skills/figma-canon/references/field-notes.md#settimeout-did-not-fire-through-the-figma-console-bridge)
- **"Things happen out of order: a font or a page is not ready when the next line runs."** An async call without `await` lets the script move on before the resource is ready. [Await every async call](../skills/figma-canon/references/plugin-api-core.md#await-every-async-call)

## Wrong render: "the data reads right, and the canvas looks wrong"

- **"New sections come out black."** `setBoundVariableForPaint` stores the base color you pass in, and a section (and an export) renders that stored color, not the variable. [A SECTION fill bound to a variable renders the base color you passed](../skills/figma-canon/references/field-notes.md#a-section-fill-bound-to-a-variable-renders-the-base-color-you-passed)
- **"A logo built from shapes renders black, and the agent says the color is bound."** On a boolean shape, a variable bound in a later call than the one that created it reads `bound: true` and keeps the literal color. [BOOLEAN_OPERATION: constraints is not assignable, and a paint binding in a later call does not resolve](../skills/figma-canon/references/plugin-api-anomalies.md#boolean_operation-constraints-is-not-assignable-and-a-paint-binding-in-a-later-call-does-not-resolve)
- **"The dark scrim behind a modal is invisible."** A black paint with paint-level transparency can fail to composite while every property reads correct. [Black translucent overlay paint can fail to composite](../skills/figma-canon/references/plugin-api-anomalies.md#black-translucent-overlay-paint-can-fail-to-composite)
- **"An icon became a giant black blob, or vanished, after the agent made it smaller."** `instance.resize()` changes the box of the instance but not always the geometry inside it; it depends on the constraints in the main component. [instance.resize() does not scale the children: use rescale()](../skills/figma-canon/references/plugin-api-anomalies.md#instanceresize-does-not-scale-the-children-use-rescale)
- **"An icon is upside down, and every measurement says it is fine."** Some icon vectors are stored mirrored; setting x and y on a clone makes Figma normalize the transform and drop the mirror. [Mirrored vectors flip when cloned and repositioned](../skills/figma-canon/references/field-notes.md#mirrored-vectors-flip-when-cloned-and-repositioned)
- **"A bottom sheet sits a few pixels off center after the agent widened its wrapper."** `frame.resize()` recomputes the constraints of the children, so a centered child slides. [frame.resize() applies child constraints: a centered child slides](../skills/figma-canon/references/plugin-api-anomalies.md#frameresize-applies-child-constraints-a-centered-child-slides)
- **"A triangle or hexagon looks irregular, and its size is right."** A native polygon puts its points on the ellipse inside its box, so width and height describe the box, not the shape. [createPolygon is inscribed in the ellipse of the box](../skills/figma-canon/references/plugin-api-anomalies.md#createpolygon-is-inscribed-in-the-ellipse-of-the-box-no-regular-triangle-or-hexagon-from-the-width)
- **"A radio button or check shows twice, or clipped."** New controls were drawn on top of a kit row whose own accessory is still visible underneath. [Replacement overlay on a kit instance: check the original accessory underneath](../skills/figma-canon/references/plugin-api-anomalies.md#replacement-overlay-on-a-kit-instance-check-the-original-accessory-underneath)
- **"In dark mode, a badge stays white and its icon disappears."** Whatever does not flip with the mode was hardcoded, in that case a raw `#FFFFFF`. [Deriving the dark version of a screen](../skills/figma-canon/references/plugin-api-anomalies.md#deriving-the-dark-version-of-a-screen-setexplicitvariablemodeforcollection-and-the-raw-hex-detector)
- **"A small button looked fine in review, and it is empty on 16 screens."** It was checked on a render of the whole section scaled down, where a 36 px button is a colored dot. [17. Scale of proof + simulating the recipient](../skills/figma-handoff-gate/SKILL.md#17-scale-of-proof--simulating-the-recipient-field-note-2026-08-paid-for-in-production)
- **"The agent said QA was complete, and I found bugs in minutes."** A screenshot at reduced scale cannot show an 8 px shift, a 1 px margin or a duplicated circle. [A reduced-scale screenshot cannot approve alignment](../skills/figma-canon/references/field-notes.md#a-reduced-scale-screenshot-cannot-approve-alignment)

## Wrong target: "the agent edited the wrong thing"

- **"It changed a card in the background instead of the one in the sheet."** A search by name from the root of a cloned screen matches the backdrop and the overlay alike. [findAll and findOne on a clone root match the backdrop too](../skills/figma-canon/references/plugin-api-anomalies.md#findall-and-findone-on-a-clone-root-match-the-backdrop-too)
- **"It planted a button on five screens it was not supposed to touch."** It aimed at a structural pattern ("the frame with an avatar and a name") instead of the layer's exact name. [Mandatory guards in batch writes](../skills/figma-canon/references/figma-execute-atomicity.md#mandatory-guards-in-batch-writes)
- **"Its audit came back empty, or full of another page's layers."** Searches on `figma.currentPage` follow whichever page is active, and the designer or another session can switch it. [findAllWithCriteria runs on figma.currentPage](../skills/figma-canon/references/plugin-api-anomalies.md#findallwithcriteria-runs-on-figmacurrentpage-another-session-can-switch-it)
- **"It says my page does not exist."** With two files paired, the active file can change by itself mid-write, so the agent is looking in the wrong file. [The active file DRIFTS on its own in the middle of a write](../skills/figma-bridge-doctor/SKILL.md#the-active-file-drifts-on-its-own-in-the-middle-of-a-write)
- **"Its writes landed in someone else's file after the bridge restarted."** Restarting a shared bridge server released another session's pinned file, and calls without `fileKey` go to whichever file is active. [Restarting a shared bridge server releases another session's pin](../skills/figma-canon/references/field-notes.md#restarting-a-shared-bridge-server-releases-another-sessions-pin)

## Components and instances

- **"Every instance suddenly shows all of its icons at once."** An instance override is tied to the id of the layer inside the main component, and replacing that layer creates a new id. [Replacing a node inside a master wipes the override on every instance](../skills/figma-canon/references/plugin-api-anomalies.md#replacing-a-node-inside-a-master-wipes-the-override-on-every-instance)
- **"It switched one tab to Selected, and the tab got the wrong icon."** The new variant has a different icon slot, and the override stayed in the slot of the old variant. [Switching a variant resets the icon to the new variant's default](../skills/figma-canon/references/field-notes.md#switching-a-variant-resets-the-icon-to-the-new-variants-default)
- **"It changed the example text in one variant, and every variant changed."** The layer is bound to a text property, and a component set keeps one default value per property. [A TEXT component property has one default value per component set](../skills/figma-canon/references/field-notes.md#a-text-component-property-has-one-default-value-per-component-set)
- **"It reset one override, and my text went back to the default too."** `resetOverrides()` clears every override on the instance, text included. [Instance manipulation: three gotchas](../skills/figma-canon/references/plugin-api-anomalies.md#instance-manipulation-three-gotchas)
- **"It cannot instance a component that is right there in the file."** Importing by key only finds published library components, not local ones. [Instance manipulation: three gotchas](../skills/figma-canon/references/plugin-api-anomalies.md#instance-manipulation-three-gotchas)
- **"It cannot put a logo inside an instance, and a stray copy appeared on another page."** An instance does not accept new children, and `clone()` places the copy next to the original, on the original's page. [An instance cannot receive children, and a cross-page clone stays on the source page](../skills/figma-canon/references/field-notes.md#an-instance-cannot-receive-children-and-a-cross-page-clone-stays-on-the-source-page)
- **"It cannot move a layer that lives inside an instance."** The position of a layer inside an instance is not an override. [Mandatory guards in batch writes](../skills/figma-canon/references/figma-execute-atomicity.md#mandatory-guards-in-batch-writes)
- **"After it nested an instance into a slot, searches on the page started crashing."** The instance was configured before it was inserted, and the references it touched point at ids Figma no longer recognizes. [Configure a nested instance only after inserting it into the slot](../skills/figma-canon/references/field-notes.md#configure-a-nested-instance-only-after-inserting-it-into-the-slot)
- **"Its new component set is huge, overlaps its neighbors and opens on the wrong variant."** Combining variants keeps each one's original position, the set does not shrink by itself, and the children get re-sorted by name. [combineAsVariants: variants keep original positions and the set does not auto-shrink](../skills/figma-canon/references/plugin-api-anomalies.md#combineasvariants-variants-keep-original-positions-and-the-set-does-not-auto-shrink)
- **"Combining frames into variants fails."** Only components can be combined into a component set, not frames. [combineAsVariants requires COMPONENT, not FRAME](../skills/figma-canon/references/plugin-api-anomalies.md#combineasvariants-requires-component-not-frame)
- **"Right after combining variants, its next step fails on layers that should exist."** The references held before combining are stale; the returned component set is the one to use. [combineAsVariants: stale references](../skills/figma-canon/references/plugin-api-anomalies.md#combineasvariants-stale-references)
- **"It turned frames into components, then crashed reading their names."** Converting a frame consumes it, so any later read of the old frame throws. [createComponentFromNode invalidates the source frame](../skills/figma-canon/references/plugin-api-anomalies.md#createcomponentfromnode-invalidates-the-source-frame)
- **"Adding an instance swap property fails, and the key is valid."** The default value of that property wanted the node id, not the component key. [addComponentProperty INSTANCE_SWAP wants the node id, not the key](../skills/figma-canon/references/plugin-api-anomalies.md#addcomponentproperty-instance_swap-wants-the-node-id-not-the-key)
- **"Placing a component times out, and the slot stays empty."** `figma_instantiate_component` sometimes times out over the bridge WebSocket. [INSTANTIATE_COMPONENT: intermittent WebSocket timeout](../skills/figma-canon/references/plugin-api-anomalies.md#instantiate_component-intermittent-websocket-timeout)
- **"It drew an icon by hand when the library already had it."** Each write was checked on its own, and over several sessions one feature piled up dozens of hand-drawn icons. [Check 4: search_design_system](../skills/figma-preflight/SKILL.md#check-4-search_design_system-if-the-write-creates-new-ui)

## Variables and tokens

- **"I asked for a translucent tint, and it came out solid."** Binding a color variable to a paint can discard the paint's opacity. The notes record two working orders and a raw rgba fallback, so read them before picking one. [setBoundVariableForPaint stomps explicit opacity](../skills/figma-canon/references/plugin-api-anomalies.md#setboundvariableforpaint-stomps-explicit-opacity) · [`setBoundVariableForPaint` drops paint opacity: bind first, set opacity after](../skills/figma-canon/references/field-notes.md#setboundvariableforpaint-drops-paint-opacity-bind-first-set-opacity-after) · [Opacity stomp warning](../skills/figma-canon/references/plugin-api-data.md#opacity-stomp-warning)
- **"It changed the opacity of a bound fill, and it stayed at full opacity."** A paint is read-only: changing its opacity in place after the bind does nothing, and spreading a new opacity into it drops the binding. [Counter-evidence and working order](../skills/figma-canon/references/plugin-api-data.md#counter-evidence-and-working-order)
- **"It bound a variable, and the color style disappeared (or the other way around)."** On one property a variable and a style cannot coexist: the last one set wins and clears the other. [Variables and styleId: mutually exclusive on the same property](../skills/figma-canon/references/plugin-api-data.md#variables-and-styleid-mutually-exclusive-on-the-same-property)
- **"After a main component rebuild, the strokes look right and the variable is gone."** Stroke overrides on instances can survive a rebuild while their variable binding is dropped. [Force-rebind strokes after master rebuild](../skills/figma-canon/references/plugin-api-anomalies.md#force-rebind-strokes-after-master-rebuild)
- **"A color pair passes contrast in light mode and fails in dark mode."** The contrast was computed with the obvious text color instead of the label's variable resolved in that mode. [Contrast per mode: resolve both colors through their bindings](../skills/figma-canon/references/field-notes.md#contrast-per-mode-resolve-both-colors-through-their-bindings)
- **"Some elements do not change when the agent switches the screen to dark mode."** Fills bound to the collection's variables flip with the mode; what does not flip was hardcoded. [Deriving the dark version of a screen](../skills/figma-canon/references/plugin-api-anomalies.md#deriving-the-dark-version-of-a-screen-setexplicitvariablemodeforcollection-and-the-raw-hex-detector)
- **"Every variable shows up in every property picker."** The variables were created with the `ALL_SCOPES` scope. [Variable scopes: never default to ALL_SCOPES](../skills/figma-canon/references/plugin-api-data.md#variable-scopes-never-default-to-all_scopes)
- **"Its imported SVG icons fail the no-raw-hex check, and some have a box behind them."** `createNodeFromSvg` keeps the SVG's literal colors, and its wrapper frame can get a stray fill. [createNodeFromSvg carries raw hex and stray wrapper fills](../skills/figma-canon/references/plugin-api-anomalies.md#createnodefromsvg-carries-raw-hex-and-stray-wrapper-fills)
- **"Reading a variable stops the script with 'Cannot call with documentAccess: dynamic-page'."** The synchronous variable getters throw in dynamic-page mode; only the async ones work. [Async getters for Variables: dynamic-page mode](../skills/figma-canon/references/plugin-api-core.md#async-getters-for-variables-dynamic-page-mode)

## Text and fonts

- **"Its text script hangs after a handful of fonts."** Awaiting `loadFontAsync` one font at a time in a loop hung after 5 to 7 loads; the cause is not established. [Sequential `await loadFontAsync` in a loop hangs the sandbox](../skills/figma-canon/references/field-notes.md#sequential-await-loadfontasync-in-a-loop-hangs-the-sandbox)
- **"A text edit died on the third text layer, and the bridge stopped answering."** The script called `getRangeAllFontNames` on every text layer in a loop. [`getRangeAllFontNames` in a loop hangs the sandbox](../skills/figma-canon/references/field-notes.md#getrangeallfontnames-in-a-loop-hangs-the-sandbox)
- **"It cannot load a font the app clearly uses."** The code loads fonts under keys such as "RobotoMono-Regular", and Figma wants the family name plus the style. [Font keys in code are not Figma family names](../skills/figma-canon/references/field-notes.md#font-keys-in-code-are-not-figma-family-names)
- **"It asked for 'Semibold', and the font failed to load."** The style is often named "Semi Bold", with a space; style names have to be checked, not guessed. [Font loading: required before text ops](../skills/figma-canon/references/plugin-api-core.md#font-loading-required-before-text-ops)
- **"It says the fonts are installed, and Figma does not list them."** A valid font file is not a registered font, web formats do not install, and an open Figma needs a restart. [Installing fonts for Figma Desktop on macOS](../skills/figma-canon/references/field-notes.md#installing-fonts-for-figma-desktop-on-macos)
- **"Reading the font size of some text layers kills the whole script."** A layer with mixed values returns `figma.mixed`, a Symbol, and returning a Symbol breaks the whole call. [figma.mixed (Symbol): "Cannot unwrap symbol" on return](../skills/figma-canon/references/plugin-api-anomalies.md#figmamixed-symbol-cannot-unwrap-symbol-on-return) · [`figma.mixed` is a SYMBOL](../skills/figma-canon/references/plugin-api-core.md#figmamixed-is-a-symbol-it-breaks-the-return-of-figma_execute) · [End deep reads with `return JSON.stringify(out)`](../skills/figma-canon/references/field-notes.md#end-deep-reads-with-return-jsonstringifyout)
- **"On the official Figma MCP server, it cannot use my custom font."** `use_figma` is documented as having no custom font support as of 2026-10. [Image bytes: plugin path](../skills/figma-canon/references/plugin-api-data.md#image-bytes-plugin-path)

## Layout and sections

- **"Its new frames land on top of each other, or on top of my work."** New top-level layers default to position (0,0). [(0,0) collisions: the find-free-space algorithm](../skills/figma-canon/references/plugin-api-anomalies.md#00-collisions-the-find-free-space-algorithm)
- **"Frames it cloned sit loose on the page instead of inside the section."** `clone()` of a section child places the copy at page level. [clone() of a SECTION child lands at page level, not in the section](../skills/figma-canon/references/plugin-api-anomalies.md#clone-of-a-section-child-lands-at-page-level-not-in-the-section)
- **"Every frame in the section shifted when it added one."** Appending to a section re-packs all of its children. [SECTION.appendChild: reflow](../skills/figma-canon/references/plugin-api-anomalies.md#sectionappendchild-reflow)
- **"Headers and captions vanished when it deleted its scratch section."** A section created or resized over existing content absorbed it silently, and removing the section destroyed what it had absorbed. [A SECTION created or resized over existing content adopts it, and remove() destroys it](../skills/figma-canon/references/plugin-api-anomalies.md#a-section-created-or-resized-over-existing-content-adopts-it-and-remove-destroys-it)
- **"It created a section over my frames, and the section came out empty."** A later note saw no adoption through the API (it attributes adoption to dragging in the UI); both observations stand. [A section created through the API did not adopt the nodes underneath](../skills/figma-canon/references/field-notes.md#a-section-created-through-the-api-did-not-adopt-the-nodes-underneath)
- **"A screen landed thousands of pixels away from where it said, and the section moved."** Children of a section use coordinates relative to the section, and a page coordinate written to one lands far away with no error. [SECTION children use section-relative coordinates](../skills/figma-canon/references/plugin-api-anomalies.md#section-children-use-section-relative-coordinates) · [Page coordinates written to a SECTION child land far away and can move the section](../skills/figma-canon/references/field-notes.md#page-coordinates-written-to-a-section-child-land-far-away-and-can-move-the-section)
- **"A frame it built does not hug its content."** After `resize()`, an auto layout frame stays fixed on its main axis and reports the old height. [Auto-layout frame stuck FIXED after resize()](../skills/figma-canon/references/plugin-api-anomalies.md#auto-layout-frame-stuck-fixed-after-resize)
- **"The height will not change, even set to hug."** A `maxHeight` inherited from the cloned source blocks it. [`maxHeight` inherited from a clone blocks hug](../skills/figma-canon/references/field-notes.md#maxheight-inherited-from-a-clone-blocks-hug)
- **"After it switched a frame from horizontal to vertical, the frame kept its old height and clips the content."** The sizing modes keep their values while the axes they name swap. [Changing layoutMode on a frame that already has auto layout freezes the dimension](../skills/figma-canon/references/plugin-api-anomalies.md#changing-layoutmode-on-a-frame-that-already-has-auto-layout-freezes-the-dimension)
- **"A dim layer or bottom sheet lands under the content instead of on top."** Anything appended to an auto layout frame enters the layout flow unless it is set to absolute. [Overlays on any auto-layout container flow into the layout](../skills/figma-canon/references/plugin-api-anomalies.md#overlays-on-any-auto-layout-container-flow-into-the-layout)
- **"After it added an overlay, the main content shrank to 1 px wide."** The overlay entered the flow of a horizontal auto layout and took the width from the sibling set to fill. [Overlay on a screen that IS auto layout](../skills/figma-canon/references/auto-layout-canon.md#overlay-on-a-screen-that-is-auto-layout-absolute-before-xy-or-the-sibling-collapses)
- **"The script died when it tried to float a badge over a cover image."** Absolute positioning needs a parent with auto layout. [layoutPositioning ABSOLUTE requires an auto-layout parent](../skills/figma-canon/references/plugin-api-anomalies.md#layoutpositioning-absolute-requires-an-auto-layout-parent)
- **"Text wraps one word per line, or a title runs over the body."** A text set to fill inside a hug frame collapses to the minimum width. [Caption FILL-in-HUG overflow](../skills/figma-canon/references/plugin-api-anomalies.md#caption-fill-in-hug-overflow)
